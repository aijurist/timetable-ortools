Combined Scheduler — Input/Output Specification

Purpose
-------
This file documents the inputs required by `CombinedScheduler` (and related modules) and the outputs the scheduler produces. Use this as the canonical I/O reference when integrating agents, building tests, or creating data fixtures.

High-level Inputs
-----------------
- `course_file` (CSV): Primary course dataset passed to `CombinedScheduler(course_file, room_file)`.
- `room_file` (CSV): Primary room dataset with room metadata (capacity, type, block, is_lab, room_number, id).
- Optional supporting files (automatically discovered or configurable):
  - `data/block_wise/techlongue.csv` (rooms fallback)
  - `day_order.csv` (department day patterns)
  - `pop.csv` (teacher day preferences)
  - `og-final.csv` or `combined_lab_mapping.json` (core-lab mapping / OG mapping)
  - `extracted_group_details_optimization_format.json` (precomputed groups; used by group creation step)

Detailed Input Schemas
----------------------
1) Course CSV (`course_file`)
   - Required columns:
     - `course_instance_id` (str/int): Unique identifier for course instance (e.g., CS101_S1_v1)
     - `course_code` (str): Course short code
     - `semester` (int): Semester number (e.g., 3,5,7)
     - `student_count` (int): Number of students in the instance
     - `practical_hours` (int): Practical hours per week
     - `theory_hours` (int): Theory hours per week
     - `teacher_id` (str/int): Assigned teacher identifier (optional)
     - `department` (str): Department name used for block mapping & shifts
     - `is_core_lab` (0/1): Whether this lab is a "core" lab requiring OG mapping
     - `virtual_id` / `co_scheduled_id` (optional): For split/co-scheduled large classes
   - Optional helpful columns:
     - `preferred_rooms` (comma-separated room ids)
     - `lab_type` (e.g., 'computing', 'laboratory')
     - `group_id` or `grouping_hint`

2) Room CSV (`room_file` / `techlongue.csv`)
   - Required columns:
     - `id` (int/str): Unique room identifier used by scheduler
     - `room_number` (str): Human-readable room number (e.g., A302, TIFAC-A401)
     - `room_max_cap` (int): Numeric capacity of the room
     - `is_lab` (0/1): Whether the room is a lab
     - `room_type` (str): e.g., 'Laboratory', 'Computer Lab', 'Theory'
     - `block` (str): Block name (A Block, B Block, C Block)
   - Optional columns:
     - `floor` (int)
     - `core_only` (0/1): If TRUE restricts to core courses
     - `tifac` (0/1) or `is_tifac` derived from `room_number`

3) `pop.csv` (teacher day preferences)
   - Expected columns:
     - `teacher_id` (str)
     - `course_code` (optional, '*' for general)
     - `preferred_days` (comma-separated list of day names or indices)
   - Notes: parsed by `_load_teacher_day_preferences()`; optional but recommended for respecting teacher constraints.

4) `day_order.csv`
   - Columns mapping department -> day pattern (e.g., Monday-Friday, Tuesday-Saturday)
   - Used by `_setup_department_day_patterns()` to compute `dept_day_patterns` and `semester_day_overrides`.

5) Core-lab mapping: `og-final.csv` or JSON mapping file
   - Purpose: map course codes (core labs) to specific lab clusters or room sets.
   - Columns/keys: `course_code`, `mapped_lab_cluster` or `preferred_room_ids`.

6) Precomputed groups JSON (optional): `extracted_group_details_optimization_format.json`
   - If present, `create_course_groups()` can ingest precomputed groups instead of recomputing from scratch.

Runtime Inputs (programmatic)
-----------------------------
- `model` (ortools.cp_model.CpModel): Created inside scheduler during `generate_combined_schedule()`.
- `lab_variables` & `group_timeslot_vars`: Dicts of CP variables created by `_create_lab_variables()` and `_create_group_timeslot_variables()`.

Outputs
-------
Primary outputs are written into the scheduler's `output_dir` (default `output/combined_schedule_<timestamp>/`).

1) JSON schedules
   - `lab_schedule.json` — Structured lab schedule with entries containing:
     - `course_instance_id`, `teacher_id`, `day`, `lab_session` (L1..L6), `room_id`, `batch_id`, `time_range`
   - `theory_schedule.json` — Structured theory schedule with entries containing:
     - `group_name`, `day`, `time_slot_index`, `room_id`, `teacher_id` (if known)
   - `combined_schedule.json` — Merged view with both lab and theory entries per group/instance

2) CSV / human-readable schedules
   - `lab_schedule.csv`, `theory_schedule.csv` produced for quick inspection

3) Logs and reports
   - `timetable_scheduler.log` already exists; scheduler writes detailed run logs including constraint application counts
   - `shift_report.json` / `.csv` generated by `_generate_shift_reports()` describing teacher shift assignments and any violations

4) Diagnostics
   - `validation_report.json` — Details about constraint violations, unsatisfied constraints (if solver couldn't satisfy all HARD constraints), and conflict traces
   - `room_conflicts.csv` — If cross-schedule conflicts detected during validation

5) Visuals (optional)
   - Heatmaps and visualization files under `output/visualizations` if `generate_course_group_distribution_heatmap()` is invoked

File Formats and Example Snippets
---------------------------------
- `lab_schedule.json` (example entry):
  {
    "course_instance_id": "BT201_S3_v1",
    "teacher_id": "T123",
    "day": "monday",
    "lab_session": "L3",
    "room_id": "R45",
    "batch_id": "B2",
    "time_range": "11:40 - 1:20"
  }

- `theory_schedule.json` (example entry):
  {
    "group_name": "ComputerScience_S3_G1",
    "day": "tuesday",
    "time_slot_index": 4,
    "time_range": "11:40 - 12:30",
    "room_id": "R12",
    "teacher_id": "T456"
  }

Validation and Sanity Rules
---------------------------
- Room capacity must be >= student_count for assigned theory rooms (enforced by `_apply_proper_theory_room_capacity_constraint`).
- Lab rooms must match course lab_type where specified (computer labs vs wet labs).
- No double-booking: (day, timeslot, room_id) must be unique across lab+theory as enforced by global registry
- For flexible lunch departments, ensure either a traditional lunch slot or valid lab-theory combos that create a natural break

Minimal example to run scheduler (pseudo-commands)
-------------------------------------------------
```powershell
python -m src.start_server --courses data/courses.csv --rooms data/rooms.csv
```

Notes / Integration Tips
------------------------
- When implementing agents, feed them the CSV/JSON inputs described here.
- Agents that propose constraints should reference column names exactly as above to avoid mismatches.
- Use `combined_scheduler.output_dir` to locate generated outputs after a run.
