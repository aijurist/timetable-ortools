Why this formulation can be more optimized:

Directness: AddAllowedAssignments is a powerful constraint that directly tells the solver the valid combinations for a set of variables. This can lead to better propagation and reduced search space compared to building the logic with many intermediate boolean variables and implications, especially if the previous implementation was complex.
Clarity: The intent is very clear.
Reduces Complex Implications: It avoids potentially complex chains of OnlyEnforceIf that might arise from trying to manually specify "if assistant takes batch 1 then primary takes batch 2, AND if assistant takes batch 2 then primary takes batch 1."
Further Considerations for Performance:

Pre-computation: Ensure that identifying primary and assistant teachers for courses is done efficiently before defining the constraints.
Variable Domains: Keep the domains of your teacher variables as tight as possible.
Symmetry: While the AddAllowedAssignments for two batches might have two symmetric solutions (P,A) and (A,P), these are distinct assignments to lab_C_batch1_teacher_var and lab_C_batch2_teacher_var. If the batches themselves are truly indistinguishable before teacher assignment and scheduling, further symmetry breaking might be needed, but usually, the named batch variables handle this.
Overall Model Complexity: If the model is very large with many other tight constraints, performance can still be a challenge. Consider breaking the problem down or using solver parameters like num_search_workers if appropriate.
By using AddAllowedAssignments, you directly express the core logic of the primary/assistant teacher allocation for the two batches in a way that the CP-SAT solver can often process more efficiently. This "enhanced prompt" to OR-Tools should provide a more streamlined path for the solver.
